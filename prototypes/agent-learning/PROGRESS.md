# 原型进展与接续入口

更新：2026-10-28。当前阶段：UI/UX 交互原型已交付，正在讨论真实数据闭环；本轮只补文档。

## 产品目标与已确认约束

面向用户本人，服务于获得 Agent 开发岗位 Offer，并逐步具备独立完成需求分析、源码定位、设计实现、调试验证与取舍解释的能力。现有工作方式是 VS Code 中与 Agent 实时协作。

- 产品覆盖个人学习与求职，不围绕 MCP 或某个当前实验构建主线。
- 用户强调主动回忆、间隔复习、相关场景交叉练习；工程实现与迁移仍需运行证据，不能以答题自评替代。
- UI 用布局、操作与状态表达流程。用户明确反对用长篇说明、重复标签代替 UI/UX。
- 当前授权范围为产品设计、原型与交接记录；真实后端接入尚未实施。
- 本原型为 AI 完整实现的实际交付，不计为用户独立开发能力证据。原有学习实践状态保留。

## 代码与运行入口

原型是独立 Git 仓库，操作 Git 时进入本目录，不要误操作 `repos/pi-mono/`。

| 文件 | 作用 |
| --- | --- |
| `dist/index.html` | 页面入口 |
| `dist/style.css` | 样式、布局、响应式断点 |
| `dist/app.js` | 页面渲染、演示数据、内存状态、事件与导出 |
| `.openai/hosting.json` | 已创建 Site 的项目 ID 和静态目录；后续沿用，勿重复创建 |
| `README.md` | 使用入口与范围 |

在本目录运行：

```sh
python3 -m http.server 4173 --directory dist
```

打开 `http://localhost:4173/?variant=A`，也可以直接打开 `dist/index.html`。上一轮临时 HTTP 服务已经停止。复制功能受浏览器权限与访问方式影响。

`app.js` 中 `state` 保存页面内存，`questions` 是演示题；`render()` 分发页面，文档级事件处理器更新状态。页面大多整块重绘，代码是一次性原型，不是正式应用架构。`design()` 还留有旧说明页面函数，但已从导航移除。

## 数据交互方案：已讨论，尚未确定实施

助手建议采用本地 Web 应用：浏览器 ↔ 本地服务 ↔ SQLite / 学习工作区；VS Code Agent 通过上下文摘要和结构化结果交接。用户问过可行性与数据交互，但尚未确认具体技术栈、数据模型或接口，不应把该建议写成既定实现。

建议的职责划分：

- 实验 `README.md`：任务契约唯一来源。
- `learning-state.md`：当前学习进度入口。更新前比较文件版本，避免并行窗口覆盖。
- SQLite：回忆尝试、复习安排、证据索引、岗位与面试记录。引用证据文件及版本，不复制全部源码与聊天。
- Agent 结果先成为待审记录，审查后再更新相应结论。功能、解释、独立程度、迁移分别记录。
- 第一阶段手动复制上下文、导入结构化结果；闭环验证后再考虑本地命令或编辑器集成。当前只有复制与导出，没有导入实现。

仍需设计：记录 ID 与来源版本、尝试和复习项的关联、导入格式与重复处理、文件冲突合并、审核与撤销、跨天复习调度。若保留云端页面与本地服务组合，还需明确连接、认证与浏览器访问边界；目前私有 Sites 发布不解决这些问题。
