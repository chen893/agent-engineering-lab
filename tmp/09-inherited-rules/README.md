## 完整契约

### 1. 项目配置

从当前 `ctx.cwd` 下的 `.pi/rules.json` 读取 JSON 对象，例如：

```json
{
  "package-manager": "使用 pnpm",
  "language": "回复使用中文"
}
```

- 文件不存在视为空配置；文件存在时，本轮保证是合法 JSON 字符串键值对象。
- key 符合 `[a-z][a-z0-9-]{0,31}`；value 为非空单行文本，不含首尾空白，内部空格保留，每条最多 200 字。所有验收场景当前项目键与会话涉及键的并集不超过 10 个；不要求超限策略。
- 文件由用户/测试在操作之间修改。每次 `/rules` 命令或普通 prompt 开始后，行为应反映该次操作开始前已完成的最新配置更新，无需重启扩展。操作期间不会修改文件；不要求监听器或缓存优化。
- 扩展不得修改项目配置或 AGENTS.md，不把项目默认值固化为会话设置；恢复会话时使用当时项目文件的值。

### 2. 命令行为

所有命令在空闲时串行执行，通过 `session.prompt` 进入真实扩展；由 `ctx.ui.notify` 反馈，不调用模型。下表中的“有效”指项目配置与会话选择共同决定的本次约定。

| 命令 | 可见行为 |
|---|---|
| `/rules set key value` | 该会话使用给定值，优先于项目同名键；也可新增项目里没有的键。此前若屏蔽过该键，设置后重新可见。 |
| `/rules remove key` | 从该会话的有效约定中去掉这个键；即使项目有默认值，也不能重新露出。之后项目更新这个键，仍保持屏蔽，直到 set 或 reset。 |
| `/rules reset key` | 撤销该会话对这个键的覆盖或屏蔽，恢复使用当前项目默认值；项目没有该键时，该键不再有效。未做过会话设置时保持继承，并给出通知。 |
| `/rules list` | 列出全部当前有效键值；没有有效约定时明确提示为空。无需显示来源或被屏蔽的键。 |

- remove 的键当前不有效时，提示“未找到”且不改变状态。对原本就不存在的键 remove，不能偷偷预设对未来项目配置的屏蔽。
- set 的 value 是 key 后的整段文本，去首尾空白、保留内部空格；不需要引号或 shell 转义。
- 缺必要参数、set 空 value、未知子命令须通知错误/用法，不改会话状态、不调用模型；提示文案自定。只验收合法 key 的行为，不扩展非法 key 规则。
- 08 的额外 get 可保留或移除；若保留应与 list 读取同一份有效值，但不要求为 get 新增验收项。

### 3. 模型输入

普通 prompt 发起的真实模型请求，其当前有效 system prompt 必须包含每个有效键及值各一次，并保留 pi 原系统指令。命令 list 与模型使用的有效约定应一致。

更新、屏蔽、reset、项目配置修改后，下一次请求应反映新值；无有效约定时不添加约定区块；多轮不累积。只检查当前请求，不要求抹除 transcript 历史。沿用 `session_rules` 区块最省事，允许调整排版并同步修正依赖排版的旧测试。

### 4. 恢复与隔离

- 会话自己的设置使用 pi 会话存储；不能靠全局变量或另一个 JSON 文件恢复。
- 销毁旧 AgentSession，以新的 SessionManager、扩展实例打开同一 JSONL，覆盖与屏蔽意图仍有效，已 reset 的键继续继承当前项目值。
- 新会话应继承项目配置，没有旧会话的覆盖或屏蔽；再次打开旧会话，原意图不受影响。
- 所有用于持久化的会话先完成一次普通 prompt，再执行命令，沿用 08 的落盘前置条件。
- 09 使用自己新建的会话文件；可以调整会话记录格式，不要求迁移 08 的旧 JSONL。
