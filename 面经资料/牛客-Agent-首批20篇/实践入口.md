# 首轮能力校准：6 个实践入口

以下是助手根据问题池设计的练习，不是原帖中的完整题目，也不是 pi agent 已存在的需求。建议先选一项完成，再按暴露的缺口选择下一项；不要求六项一起做。

默认先在小实验中校准能力。进入 pi agent 实际仓库后，再确定版本、接口和对应代码位置。可以查文档，先自己分析和尝试，再按需使用 AI；记录获得了哪些帮助。

## 1. 追踪并修改一个最小 Agent Loop

关联：Q001、Q003、Q004；原帖见问题池对应来源。

- 任务：用可控的模拟模型实现“请求工具 → 执行工具 → 回传结果 → 生成最终回答”的流程。先写出预测的消息与状态变化，再实现。
- 验收：工具调用与结果能对应；未知工具、非法参数和工具异常有明确处理；达到指定步数后停止；无需真实模型也能重复验证。
- 证据：一条正常轨迹和至少两条失败轨迹，解释由模型决定什么、由运行时保证什么。
- 变式：一轮返回多个工具调用时，如何保持结果对应关系？

## 2. 为请求实现有边界的重试

关联：Q034；原题来源主要为 M07，以下增加了验收约束。

- 任务：实现支持重试次数和间隔的请求包装器，先明确“重试 N 次”是否包含首次请求。
- 验收：首次成功不重试；前两次失败后成功时次数准确；达到上限后返回错误；能观察各次调用及间隔。用模拟请求验证，不依赖真实网络偶发错误。
- 证据：调用次数、结果与失败输出。
- 变式：增加取消能力，验证等待期间取消后不会再次发起请求；解释有副作用的请求为何不能盲目重试。

## 3. 实现一个小型 Skill 加载器

关联：Q005、Q006；基础题来自 M12。

- 任务：按 M12 指定的目录形式发现技能、读取 YAML 元数据，并按名称调用脚本。先自行定义最小元数据字段。
- 验收：能发现并运行两个示例技能；重复名称、缺失配置、脚本不存在与执行失败都有明确结果。
- 证据：目录结构、调用示例和失败场景；解释元数据、指令与可执行工具的职责。
- 变式：新增技能时不修改加载器代码。这里的目录格式仅用于练习，不宣称与现有 Agent 框架兼容。

## 4. 在固定上下文预算内保留必要信息

关联：Q011、Q012。

- 任务：给定包含用户消息、工具调用与结果的历史，设计超预算后的处理方式。可先用字符数近似预算，但必须注明它不等于真实 token 数。
- 验收：最终输入符合预算；固定的系统约束仍保留；没有孤立的工具结果或丢失对应关系；信息被删减时能说明损失。
- 证据：压缩前后对照、边界样例及一次信息损失分析。
- 变式：面对单条超大工具输出，是否仍能满足上述条件？

## 5. 实现可验证的并发调度器

关联：Q071；基础题来自 M17。

- 任务：运行一组耗时不同、部分失败的异步任务，限制同时执行的数量。先澄清入队顺序、启动顺序、完成顺序与结果顺序。
- 验收：活动任务数从不超过上限；一个任务失败不阻止其他任务；每个任务只执行一次；结果可追溯到输入任务；能处理空任务列表和非法并发上限。
- 证据：每次启动与结束的轨迹，以及成功、失败结果。
- 变式：加入取消尚未启动任务的能力，说明已经运行的任务如何处理。

## 6. 用证据验收一次 AI 辅助修改

关联：Q026、Q030、Q074。

- 任务：选择前面完成过的一个实验，提出新的小需求。先独立写验收标准，再让 AI 辅助实现；检查差异并验证关键行为。
- 验收：能解释关键改动、识别实现假设、执行验证，并指出尚未覆盖的风险。没有发现缺陷也应如实记录，不为了练习虚构问题。
- 证据：需求、修改前后差异、验证结果、AI 协助范围与个人决策。
- 变式：改变一个约束，先自己预测哪些代码需要调整，再验证预测。

完成后使用[验证记录模板](验证记录模板.md)，并回到[问题池](问题池.md)更新状态。通过一个实验只证明相应范围的能力，不代表掌握整个模块或能完成仓库大多数需求。
