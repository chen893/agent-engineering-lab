# 超大工具输出的按需读取

在 `output-extension.ts` 实现一个 pi 扩展，使 `diagnose_log` 工具的大文本结果可以有限展示、按需读取。入口为默认导出的扩展注册函数；具体内部模块、类型和读取工具接口由实现者定义。

诊断工具可能返回数万字符的日志。模型需要先获得有限文本及原文读取入口，再读取所需部分，避免每次将整份日志放入模型请求。

## 业务契约

| 项目 | 要求 |
| --- | --- |
| 输入 | `diagnose_log` 的最终工具结果，只有一个 text content 块；成功与失败均可能产生长文本 |
| 展示预算 | 每个受本扩展管理的工具结果，所有 text 块拼接后的 JavaScript `string.length` 不超过 2,000；提示与读取定位信息也计入预算 |
| 小结果 | 原文长度不超过预算时，原样保留文本及原有成功/失败含义 |
| 大结果 | 原文完整保存到本地；返回文本应明确说明内容不完整，并让模型知道如何读取原文 |
| 原文读取 | 提供独立工具按需读取原文的一部分；参数、定位方式、分页单位及返回格式由你定义，并在 design.md 写清楚。每次读取结果也遵守展示预算 |
| 可恢复性 | 关闭并重建扩展后，已有读取定位信息仍能使用；多次诊断的原文互不覆盖 |
| 访问范围 | 只允许读取本扩展保存的产物；无法识别的定位信息或无效读取参数返回明确工具错误，随后合法调用仍可工作 |
| 结果语义 | 处理输出不能把原诊断失败改成成功；后续模型请求中工具调用与结果仍正确关联 |

原文保存目录由 `createOutputExtension({ artifactDir })` 接收，使用绝对路径。默认导出可采用当前项目下 `.tool-output`。目录可自动创建；无需设计清理策略。

边界：顺序调用、文件读写可靠、没有恶意修改磁盘或符号链接、无需跨项目授权；不处理图片、structuredContent、流式中间输出或进程中途崩溃。字符预算不代表 token 预算。不要求改动 pi 源码，也不要求调用付费模型。

## 设计与实现

先在 `design.md` 写清楚你选定的接入位置及源码证据、对外读取接口、保存方案和关键验证输入/预期/观察点，再集中实现，无需等待逐项批准。原文读取接口中有影响验收的选择，以你明确写出的设计为准。

`diagnose_log` 是测试用诊断工具，由你在测试中注册，可返回确定的多行日志。扩展应处理它的结果，不要把有限展示逻辑直接写进诊断工具。

## 验收

提交实现、设计说明与可复现测试。验证应覆盖上述契约，具体场景由你选择，测试代码可在你选定场景后交 AI 编写。

至少提供一条真实 pi 扩展加载与 AgentSession 调用链：离线模型调用诊断工具，收到受限结果，再根据结果中的定位信息调用读取工具，在下一次模型请求中观察返回原文。记录处理前后文本长度和实际读取内容。只直接调用 handler 或只使用 Agent Core 手动拼装结果不足以证明扩展接入成功。

可复用已有实验中的离线模型设施与会话测试环境；需自行定位并解释本次用到的运行时入口。
